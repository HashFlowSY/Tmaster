# 05 — 注册页重做

**What to build:** 一条完整、合理、手机端从容的注册体验。命主打开注册页：布局有呼吸留白、键盘弹起时当前输入框不被遮挡；输入时字段失焦即校验、确认密码在两框都碰过后实时比对；所有错误就地显示在对应字段（邮箱格式、密码长度、两次不一致、该邮箱已注册），不再有 `Alert` 弹窗打断；可一键显/隐密码；密码说明文案与实际规则一致（去掉并不强制的「含字母与数字」承诺）；能点开并阅读《用户协议》《隐私政策》后再勾选同意；注册成功后进入 onboarding（生辰引导）。

**Blocked by:** 01（错误信封 + `fields`）、02（`Field` 错误态/显隐、`Screen` 键盘避让、校验/映射纯函数）、03（法务页作为可点链接的落点）。

**Status:** ready-for-agent

- [ ] 布局改为键盘避让 + `flexGrow` flex 列 + 呼吸留白：矮屏可滚、高屏有呼吸；留白仅作用于 auth，**不动全局 `Screen`**（不回归已验收的其余 8 屏）。
- [ ] 邮箱/密码失焦校验、确认密码两框都碰过后实时比对，提交做总校验；错误全部就地内联，**移除所有 `Alert.alert`**。
- [ ] 服务端 `email_taken` 内联到邮箱字段；`validation` 的 `fields` 落到对应字段；网络/`internal` 走 Toast。
- [ ] 密码框可一键显/隐；helper 文案与 min-8（无复杂度）一致。
- [ ] 《用户协议》《隐私政策》可点，跳转到票 03 的法务页；未勾选同意时就地提示、不弹窗。
- [ ] 注册成功 `→ /onboarding`（ADR-0004 门槛不变）；提交中按钮加载态、禁重复点击。
- [ ] 校验与错误映射复用票 02 的纯函数（屏幕保持薄接线）；改版后做一次 iOS + Android 真机视觉核对（软门槛，不阻断）。
